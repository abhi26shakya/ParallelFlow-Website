## AI agent = Model + Loop + Harness

An AI agent is a system that can reason, take actions in a given environment, and deliver an output from a single command, with minimum human involvement.

Every agent is built from three parts:

- **Model:** the brain that reasons.
- **Loop:** the program that keeps the model working until the job is done.
- **Harness:** everything around the loop that lets the model act: tools, context, memory, permissions and more.

## The Model

The model is a stateless machine: it takes an input, reasons over it, and returns an output. Stateless means it remembers nothing between calls; everything it needs must be sent with each request.

- **Input:** text, image, audio or video, depending on the model.
- **Output:** usually text (including structured text like JSON and tool calls) or images.
- **How it reasons:** from its parametric knowledge, meaning what it learned during training and stored in its weights. Anything newer than its training data must be supplied from outside.

### Types of models

The split comes from psychologist Daniel Kahneman's idea of two modes of thinking: fast and intuitive (System 1) versus slow and deliberate (System 2).

**System 1 models.** These models are designed to make quick decisions. They choose the most suitable answer from a predefined set of options and provide a confidence score. They are fast, cost-effective, and best suited for simple, well-defined tasks.

- **Use cases:** routing requests, spam and safety filtering, tagging, yes/no decisions, gating tool calls inside an agent.
- **Examples:** Jev from TypeSafe AI; Laya, an open-source 421M-parameter alternative under Apache 2.0; and customized classifiers fine-tuned on private data.

**System 2 models.** These models analyze problems step by step before generating an answer. They are better suited for complex tasks that require deeper reasoning and understanding. They generally provide more reliable and accurate results, but take more time and computational resources.

- **Use cases:** coding, content generation, research, planning. These are the most widely used models today.
- **Examples:** the Claude, GPT, DeepSeek, GLM and Gemini families.

In a real agent, the two work together.

## The Loop

An agent loop is a continuous cycle in which a model receives input, decides what to do, performs an action, and observes the result. This process repeats until a stopping condition is reached.

The most widely used loop is ReAct (Reason + Act), introduced by Yao et al. in 2022. Each cycle has three steps:

1. **Reason:** the model decides what to do next.
2. **Act:** it calls a tool (run code, search, read a file).
3. **Observe:** the tool's result goes back into the model's input.

**The loop stops when:**

- The model produces a final answer without requesting another tool call.
- The maximum number of steps or cost limit is reached.
- A human manually stops the process.

## The Harness

The harness is the system around the loop. It provides the utilities the model needs to reason and act.

### Tools

Functions the model can call to act on the execution environment, such as reading a file, running a shell command, searching the web or sending an email.

The model only requests a tool call; the harness actually runs it and returns the result.

### Execution environment

The place where actions run: a developer's laptop, a sandboxed container, a cloud computer, or a browser. Sandboxing limits the damage if the agent does something wrong.

**Filesystem.** Every execution environment comes with a filesystem, the agent's persistent workspace. It is where the agent reads inputs, writes outputs and saves intermediate work.

It also matters for the rest of the harness: memory files, project rules and skills are stored here, subagents share results through it, and long tasks can save progress to files so work survives beyond the context window.

### Context

Everything placed in the model's input on each turn: system prompt, the user's task, relevant files, tool results and conversation history.

The context window is limited, so the harness must decide what to include, summarise or drop.

### Memory

Memory is the mechanism that allows an AI agent to store, retrieve, and reuse information across multiple model calls or sessions.

Since models are generally stateless, the agent harness manages memory by saving important information in files, databases, or other storage systems, and loading relevant information back into the model's context whenever needed.

Memory helps an agent retain previous interactions, understand ongoing tasks, remember user preferences, and maintain project-specific knowledge without having to start from scratch every time.

**Types of memory**

1. **Short-term memory (working memory).** Stores information needed for the agent's current task or conversation. It includes recent messages, current task details, intermediate results, and temporary information. _Example:_ remembering the last few messages while answering a user's question.
2. **Long-term memory.** Stores information that needs to be retained across multiple conversations or sessions. It allows the agent to recall information even after a session has ended. _Example:_ remembering facts, knowledge, records, or summaries of past interactions and experiences.

### Security and permissions

Rules on what the agent may do and when it must ask first. For example: read files freely, but ask before deleting anything or spending money. Sensitive data like passwords stays out of the model's reach.

### Subagents

Child agents that the main agent spawns for a focused sub-task, each with its own fresh context. They keep the main context clean and allow work to run in parallel.

### Skills

Packaged instructions, scripts and resources for a specific kind of task, loaded only when relevant.

_Example:_ a skill for creating PDFs or following a team's code-review rules.

### Feedback and validation

Feedback and validation are mechanisms used to check whether an agent's output meets the required standards. They use tools such as unit tests, linters, compilers, and schema validators to identify errors or missing requirements.

### Human in the loop

Points where a person reviews, approves or corrects the agent, such as approving a risky command, a payment, or an email before it is sent.

## Why Agents Differ

Most AI agents can be built around the same foundation model and a shared harness core. The core execution mechanism remains largely the same: receive a task, reason, select tools, execute actions, observe results, and repeat.

What makes these agents behave differently is how the shared harness is configured for a particular domain. Four factors primarily shape their behavior:

- **Context:** what information is provided to the model determines what it understands and reasons about.
- **Tools:** what tools are available determines what actions the agent can perform.
- **Execution environment:** where the agent operates determines how it accesses resources, executes tasks and maintains persistence.
- **Skills:** what domain-specific knowledge and procedures are available determines how effectively it performs specialized tasks.

## Three Agents Compared

Three real categories show how the harness shapes the agent.

| | Coding harness | Always-on agent | GTM harness |
| --- | --- | --- | --- |
| **Harness core** | Shared agent loop, context manager, tool registry, permissions, memory and orchestration | Same shared core | Same shared core |
| **How it starts** | Developer gives a task | A goal set once; works in the background | Leads, buyer signals or CRM events |
| **Context** | Codebase, error logs, project rules file | User's goals, preferences, connected accounts | CRM data, account history, buyer signals |
| **Tools** | Filesystem, shell, Git, tests, code editor | Browser, terminal, files, sign-in to the user's apps | CRM, email, enrichment and campaign tools |
| **Execution environment** | Developer's machine or sandbox | Its own cloud computer, running 24/7 | Cloud infrastructure connected to business systems |
| **Filesystem / data access** | Reads and modifies project files directly; executes shell commands | Uses its own persistent filesystem and browser environment | Primarily reads and updates structured CRM records and shared business data |
| **Feedback** | Tests, compiler, linter | Progress reports to the user | Replies, meetings booked and conversion metrics |
| **Human in the loop** | Approves risky commands, reviews code | Approves sensitive actions; password changes stay with the user (Dots) | Trust-gated autonomy: more freedom as trust grows |
| **Examples** | Claude Code, Codex CLI, Pi | Grok Bot, OpenAI Dots, Hermes, Clawdbot | Multi-agent sales and marketing systems |

A coding harness is a focused pair-programmer working on your machine. An always-on agent is a digital coworker with its own computer that keeps working while you are away. A GTM harness is a team of agents wired into the sales stack.

> Same idea (model + loop + harness), but three very different agents.

## Conclusion

An AI agent is a model that reasons, a loop that keeps it acting, and a harness that gives it context, tools, an environment and guardrails. The model sets how smart the agent can be; the harness decides what that intelligence is used for.

**The key architectural principle:** build one reusable harness core, and configure it with different context sources, toolsets, execution environments and domain skills to produce specialized agents.
